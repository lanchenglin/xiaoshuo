# 后续本地开发任务（可交给Codex / Claude / Hermes）

## 先保持现有可运行基线

1. 阅读README、ARCHITECTURE、STATUS，不把演示模式当真实模型。
2. 使用独立虚拟环境运行全部测试，禁止把data/.env/Key提交到Git。
3. 先用用户自己配置的兼容API跑2章，每章800–1500字符，记录实际调用usage、模板表达问题、人物状态、修订轮数、保真拒绝率和token消耗。
4. 再扩至10章、30章。没有长篇实测不要直接宣称可稳定写百万字。

## 第一优先级：实机闭环

- 在用户Windows/WSL运行原生和Docker，测试暂停后重启、网络断开、模型401/429/超时。
- 为用户实际模型增加可选 `max_completion_tokens` / `max_tokens` 参数适配，需通过真实协议回归。
- 研究输入的真实作品网址，逐站增加站点adapter，不改变通用采集器公网安全边界。
- 增加基于真实目录的章节覆盖表。每章记 title/index/url/captured/status，绝不把目录存在当正文已获取。
- 为网站robots的crawl-delay/request-rate提供显式调度；目前默认串行1秒间隔，不宣称完整限速协议支持。

## 第二优先级：更可靠的长篇质量

- 细化场景事务、人物知识图、不可变世界规则和伏笔承诺，减少仅依赖模型评审的不足。
- 审稿器与写作者分开配置，记录评分漂移和误判，不把高分当市场验证。
- 增加短篇/长篇风格样本人工对比集；评价信息保真、可读性、人物声音，不以AI检测分数为目标。
- 引入可追踪、可回放的混合检索；维护active/closed/superseded事实版本。
- 对最终审查问题提供“影响范围预览→用户授权→重写受影响章节”流程，而非直接毁掉整本。

## 第三优先级：上游后端adapter

- Oh Story：单独隔离工作目录、固定版本、收集结构化产物并验证；不允许上游在用户任意目录运行，保留上游许可证。
- Biz：先重新核实源码许可、数据模型和API，不把未完成的adapter显示为可用后端。
- Humanizer：当前真实内置，保持固定版本；允许用户可见地选择版本/关闭，新增兼容测试和上游diff审查。

## 需要保留的硬约束

- 一书一套权威设定。已验收正文不可被润色静默破坏。
- Token预算检查在请求前，未知计费不得显示为0或真实供应商账单。
- 章节字数口径统一：不含空白、含标点Unicode字符。
- 原文/网页中的指令不赋权；API密钥不进提示词、前端、导出或日志。
- 私网URL防护覆盖重定向、IPv6映射与混合DNS结果。
- 每次功能变更增加测试；不得把mock通过写成真实供应商验收。
